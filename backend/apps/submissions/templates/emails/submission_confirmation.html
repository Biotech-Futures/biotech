{% comment %} Standalone rather than {% extends "emails/base.html" %}. The shared base paints a solid dark-green header bar, hardcoded rather than exposed as a block, and the organisation's own emails have no such bar — logo and wordmark sit directly on the card. Matching the house style therefore meant either editing the shared base, which restyles seven templates across five other apps, or owning the whole shell here. This file takes the second option so nothing outside this feature is affected. The trade-off: if the shared base is later restyled, this template will not follow. That is accepted deliberately — email chrome is being unified during the integration step, at which point this can be folded back into whatever base survives. Wording follows the copy the client supplied. Component statuses are "Submitted" or "Absent" — their preferred term for not-yet-submitted, which is not deadline-sensitive.
