启动
1. 打开 Docker Desktop。
2. 双击本目录 start-demo.command；服务就绪后会在独立的 Chrome 新窗口打开 Analytics。
   不会往已有工作窗口追加标签页；不修改系统默认浏览器设置。
   首次启动会编译前端，之后源码未变时直接复用；演示使用编译版本，不使用开发热重载。
   若服务已经运行，会复用服务并新开窗口；本次启动前端时，请保持 Terminal 窗口开启。
   启动失败会显示错误并等待按回车，不会直接关闭窗口。
   原先 tmp/llm-preview-20261027-1zyclbhd/start-preview.command 也已转向这个入口。
3. 打开 http://127.0.0.1:5187/#/analytics。
4. 选择 Password Sign-in，使用以下本地合成演示账号：
   Admin：synthetic.admin.0001@team4-synthetic.biotech.test，密码：admin123。
   Student：synthetic.student.0001@team4-synthetic.biotech.test，密码：student123。
   生成器后续生成 Admin / Student 也使用对应密码；其他角色保持原配置。
   此文件不保存 AI key。

手动 / 自动两种独立入口（最新界面）
页面提供 Manual configuration / 手动配置 与 Automatic configuration / 自动配置，两者二选一。
- 手动配置：原数据数量、公告/邮件、分布与时间合并在一起，使用本模式的生成按钮。
- 自动配置：只填 Target student count / 目标学生人数 和 Random variation (±%) / 随机浮动。
  基于固定 120 学生预设按比例计算各项；学生人数精确，管理员固定 2 个。
  其他每项数量独立在 ±N% 内波动并取整；小规模至少保留 1 条必要记录，报名量受容量约束。
  预览立即显示完整数量；Randomize again / 重新随机 可换一组，生成使用当前显示的数量。
  自动模式直接使用自己的生成按钮，无需填写或应用手动表单，也不会覆盖手动输入。
  自动采用 Analytics coverage、Analytics 邮件预设与当前 UTC 时间；邮件收件人由受众派生，
  因此关联行不保证严格同比。支持 1–10,000 学生、0–50% 浮动，邮件明细保守预算超 200 万时拒绝。
两种模式都先显示清库确认，再清空当前演示库并生成；修改参数或切换模式不会写数据库。
1000 学生、±0% 示例：100 教师、200 导师、200 小组、6000 消息、5000 登录、1500 任务、
250 资源、10000 访问、100 公告、400 邮件批次、100 活动、1000 报名。
1000 学生、±10% 的独立数据库实测已完成：生成与迁移约 18 秒，关系、指纹、邮件 API 及密码校验通过。
为缩短大规模生成时间，本地合成账号按角色每次只计算一次标准密码哈希；产品认证逻辑未改。

邮件自定义配置（v7）
在 Announcements & email batches 中选择 Custom batches。
- Announcements：公告数量；与邮件批次数独立，同一公告可以有多次投递。
- Total email batches：准确的总批次数，不会再额外生成等量系统邮件。
- First / Last batch (UTC)：设置发送起止时间，批次在区间内等间隔排列；单批次使用起始时间。
  批次间至少间隔 1 秒，末批需早于 Dataset clock 至少 20 秒，表示已完成的合成发送记录。
  Use recent 24 hours 会把数据时钟设为现在，并设置最近 23 小时至 5 分钟前的发送区间。
- Email type：公告或 8 种系统邮件，也可选 Mixed 轮换全部 9 种。
- Delivery result：All delivered / Partially delivered / All failed，或 Mixed 混合结果。
  部分成功需要至少 2 个收件人；失败人数为人数的一半向下取整，其余为成功。
  只有 1 个收件人时，Mixed 仅生成全成功、全失败。
- Recipients per batch：每批的不同收件人数。只使用活跃合成账号，界面显示当前上限；
  默认 158 个账号中有 81 个活跃账号。增加相应用户数量可提高上限。
类型、结果、人数旁各有 Random 按钮：点击直接填入一个可见值，适用于全部批次，生成前仍可编辑。
同样的配置与 seed 可以重建相同数据；配置会保存，Load its config 可恢复数据库中的完整配置。
自定义时间窗口会保留，不会在重新打开页面时自动改为今天；彩排时可点击 Use recent 24 hours。
自定义公告使用指定账号受众，发送统计、收件人明细和公告受众保持一致。
需要角色/小组受众分布演示时，选择 Analytics preset。Opened / Clicked 等仍不伪造。
Equivalent command 同步提供上述配置对应的 CLI 参数。

检查与命令行
  ./tools/local_db/run status
  ./tools/local_db/run verify
  ./tools/local_db/run test
run 入口已指向新演示库；GUI 复制出的命令也使用它。
verify 校验行数、关系、每批邮件与收件人计数以及固定数据指纹；正常登录不再被视为修改种子数据。
如需固定时间复现，可在 GUI 使用 Load its config，或将明确的 --as-of 参数传给 run bootstrap。
bootstrap 与 GUI 相同，会清空当前目标演示库并重新建表、生成和校验。
需要保留当前数据库时可使用 refresh 创建另一个新快照。

建议演示顺序
1. Overview：总体数字与 Attention Required。
2. Users / Groups / Mentors：角色分布、未分组学生、导师覆盖和容量。
3. Activity / Messages / Registration：日期筛选、明细和统计口径。
4. Resources：总点击、独立用户、按资源/日期比较及 Summary / Details / Daily usage CSV。
5. Email Monitoring：两邮箱的 24 小时用量，类型/状态过滤，收件人搜索和单次发送的收件人 CSV。
6. AI：点击右上角帮助按钮。

已经实测的 AI 问题
  如何导出资源使用统计的 CSV？
  Why are opened email counts unavailable in Email Monitoring?
  How many active users do we have right now?
第一个问题应给出 Resources Analytics 的导出步骤和链接。
第二个问题应说明缺少 provider events，不能声称已有打开率统计。
第三个问题应说明助手不能读取实时数据库，并引导至 Activity 查看实际数据。
AI 当前提供基于角色的站内帮助；没有新增实时数据查询功能。
真实模型回答需要网络和已有私密 key。失败时使用本地 FAQ 回退；回退不能当作真实模型调用。
