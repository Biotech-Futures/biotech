Four steps to prepare your demo第一次使用：按这四步操作

  1. Load the current database configuration or restore the form defaults. Neither action changes database data.先选择起点。想沿用当前库，点击页面底部「载入到手动模式」；想重新配置，点击「恢复默认参数」。这两个按钮都只修改表单，不会写数据库。
  2. Choose Manual mode for exact field-by-field settings, or Automatic mode for a student count and variation. Each mode has its own generation button.选择生成模式。手动模式可逐项配置数量、邮件和时间；自动模式只填写学生数与浮动比例。两种模式各有生成按钮，切换时互不覆盖参数。
  3. In Manual mode, check the dates. Automatic mode uses the current clock. Review the quantities, then use the selected mode's generation button and confirm the reset.检查时间再生成。手动模式展示当天邮件统计时可点「使用最近 24 小时」；自动模式使用当前时间。查看数量预览，再点击当前模式的生成按钮并确认清库。
  4. After success, reload the demo website and sign in again so it reads the new data.等待成功，再登录网站。进度显示「生成成功 / succeeded」后，刷新演示网站并重新登录，避免继续显示旧缓存或已失效的会话。

Announcements and email batches are separate公告条数 ≠ 邮件批次数

An announcement is content, a batch is one send, and each recipient outcome belongs to one address in that send. Both content and recipients may be reused across batches.公告是一条内容；邮件批次是一轮发送；收件人结果是一轮发送中每个地址的结果。同一公告可以发送多次，同一个人也可以出现在多个批次中。

Analytics preset adds as many system batches as announcement batches: 24 + 24 = 48. It supplies varied audiences and edge cases.统计演示预设：预设公告批次填 24，会再增加 24 批系统邮件，合计 48 批。适合展示不同角色、小组受众和边界情况，人数与结果由预设规则安排。

Custom batches uses the exact total. Announcement quantities stay independent; explicit recipients keep counts and details aligned.自定义批次：邮件总批次填 48，最终就是 48 批，不会翻倍。公告数量独立；自定义公告按具体账号确定收件人，保证统计与明细一致。

Delivery outcomes and Random buttons投递结果与随机按钮

All delivered or All failed applies to every recipient. Partial delivery needs at least two people; failures are half the count rounded down. For 27 people: 14 delivered and 13 failed.全部成功 / 全部失败：每批全部收件人使用该结果。部分成功：至少 2 人，失败人数为一半向下取整；例如每批 27 人，得到 14 成功、13 失败。

Mixed rotates types and outcomes across batches. With one recipient, Mixed results use only success and failure.混合：类型在九类之间轮换；结果在成功、部分成功、失败之间轮换。只有 1 名收件人时，不会生成「部分成功」。

Each Random button changes only its adjacent visible setting. It does not generate data or randomize every batch independently.随机：只修改旁边那一项，结果立即显示，可以继续手动修改。它不会直接生成数据，也不是逐批随机；生成时会使用最终表单值。

Recipient counts and totals每批人数与统计总量

Recipients are distinct active synthetic users within each batch. The default 158 accounts include 81 active users; the field displays the current capacity.每批只选择不同的活跃合成账号，所以人数上限不是所有账号数。默认 158 个账号中有 81 个活跃账号；调整用户数量后，字段下方会显示新的上限。

48 batches × 27 people creates 1296 recipient outcomes, not 1296 unique people. Total outcomes are limited to 2,000,000.例如 48 批 × 每批 27 人＝1296 条收件人结果，不代表 1296 个不同的人。每批相同人数时，总量可直接这样核对；总收件人结果上限为 2,000,000 条。

Explicit rows excludes some derived relationships. Messages include soft-deleted examples that Analytics does not count as visible messages.「基础记录数量合计」不包含自动衍生的全部档案、成员关系等行。消息还包含软删除样本，因此 Analytics 可见消息数可能小于输入的消息总数。

Understanding UTC and the dataset clockUTC 时间怎么填

All three fields use UTC. Inputs are not interpreted as local time. At UTC+11, local 14:30 corresponds to 03:30 UTC.首批、末批和数据时钟都使用 UTC，不会自动把输入当成本地时间转换。例如当地时差为 UTC+11 时，本地 14:30 对应 UTC 03:30。

Batch times are evenly spaced, at least one second apart; one batch uses the first time. The dataset clock anchors the whole dataset, and the last batch must finish at least 20 seconds before it.首批／末批决定邮件时间区间，批次在其中等间隔排列。多批次之间至少间隔 1 秒；单批次使用首批时间。数据时钟是整份样例的时间基准，末批至少早于它 20 秒。

Use recent 24 hours sets the clock to now and the interval to 23 hours ago through 5 minutes ago. Refresh these dates before your presentation; stored data does not move with the real clock.使用最近 24 小时会把时钟设为现在，区间设为 23 小时前至 5 分钟前。正式展示滚动 24 小时指标前建议重新设置；数据不会随真实时间自动更新。

Scenarios, seeds and configuration recovery场景、种子与配置恢复

Analytics coverage provides varied and edge-case examples. Uniform supports baseline totals. The seed changes assignments, not requested quantities.统计覆盖场景包含未分组、无导师、活跃和不活跃等差异；均匀分布场景适合核对较均匀的基础总量。随机种子影响分配方式，不改变指定数量。

Load into manual mode restores saved settings and switches to Manual mode. Refresh rereads database status. Restore defaults resets the form. Only a confirmed generation writes to the database.载入到手动模式会切换至手动模式，并把数据库里保存的数量、类型、日期和种子填回表单；刷新状态只重新读取库信息；恢复默认参数只恢复表单。只有点击生成并确认后才会写库。

Exact replay requires the same settings, seed and clock. The fingerprint checks reproducibility. The equivalent command uses the same configuration.复现需要保持所有参数、种子和数据时钟相同。数据指纹用于核对生成结果，不是密码；等效命令可以复制到终端执行相同配置。

Reset scope, sign-in and data boundaries清库范围、登录与数据边界

Generation clears all data, extra tables and sessions in the displayed local demo database, then rebuilds it. Other databases are unchanged. A failed reset rolls back completely.每次生成都会清空下方显示的当前本地演示库，包括未知记录、额外表、旧登录会话；随后重建表结构并生成。其他数据库不会被清空，失败时整个事务回滚。

Reload the demo website and use Password Sign-in with the Admin or Student credentials shown above.生成后刷新演示网站，选择 Password Sign-in。管理员：synthetic.admin.0001@team4-synthetic.biotech.test，密码 admin123；学生：synthetic.student.0001@team4-synthetic.biotech.test，密码 student123。

Generation does not send email. Delivery outcomes are samples; unsupported open and click metrics remain unavailable.这些是合成记录，不会真正发送邮件。投递成功／失败只是样例结果；打开率、点击率等缺少真实来源的指标仍保持不可用，不能由生成器伪造。
